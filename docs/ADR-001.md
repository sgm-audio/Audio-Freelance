# ADR-001: LangGraph DAG for Pipeline Orchestration

**Date:** 2026-09-13
**Status:** Accepted
**Deciders:** SGM

---

## Context

The audio-freelance system needs to orchestrate a multi-phase pipeline: search → dedup → deep-fetch → score → generate → review. Each phase has different failure modes, retry characteristics, and data dependencies. The pipeline must be:

- **Observable:** Each phase should be individually loggable and metrics-trackable
- **Extensible:** New phases (e.g., automated outreach, ARA host integration) should be addable without rewriting existing nodes
- **Resilient:** A failure in one search tier should not cascade to others
- **Debuggable:** State at each phase should be inspectable for troubleshooting

## Decision

**Use LangGraph `StateGraph` for pipeline orchestration**, with direct async execution as the primary runtime and LangGraph as the compile target for future graph-based extensions.

### What we chose

- `langgraph.graph.StateGraph` with typed `PipelineState` (TypedDict)
- Nodes: `search_all` → `generate_translate` → `generate_outreach` → `queue_for_review` → `notify_hot` → `await_human_send`
- Conditional edges via `route_by_verdict` (hot/warm/cold paths)
- Direct `run_pipeline()` async function as the primary execution path (bypasses LangGraph runtime for reliability)
- LangGraph `build_pipeline().compile()` as a secondary entrypoint for graph-based workflow extensions

### What we considered

| Option | Pros | Cons | Verdict |
|--------|------|------|---------|
| **LangGraph StateGraph** | Typed state, visual graph, conditional edges, checkpoint support | Learning curve, runtime overhead for simple DAGs | **Chosen** |
| Plain async/await | Zero dependencies, fastest execution | No state inspection, hard to add phases, no graph visualization | Rejected |
| Airflow / Prefect | Mature orchestration, scheduling, UI | Massive dependency weight, overkill for a solo-tool pipeline | Rejected |
| Custom DAG class | Full control, minimal deps | Reimplements what LangGraph provides, maintenance burden | Rejected |
| Celery + Redis | Distributed execution, retry queues | Requires Redis broker, overkill for single-machine pipeline | Rejected |

## Consequences

### Positive

1. **Typed state flows through the entire pipeline.** `PipelineState` is a TypedDict with 18 fields — every phase reads/writes typed data. No string-keyed dicts or `**kwargs` soup.

2. **Graph visualization for debugging.** `build_pipeline().compile()` produces a directed graph that can be rendered for documentation and debugging.

3. **Conditional routing by lead verdict.** `route_by_verdict()` enables hot-path fast-tracking without if/else chains scattered across phases.

4. **Extensibility for future phases.** Adding a new node (e.g., `send_outreach`, `schedule_followup`) requires only: (a) write the node function, (b) add it to the builder, (c) wire the edge. No existing code changes.

5. **State checkpoint potential.** LangGraph's checkpoint system enables pause/resume, which is critical for the human-in-the-loop approval gate at `await_human_send`.

### Negative

1. **Runtime overhead for simple pipelines.** LangGraph adds ~50ms per node transition. For a pipeline that runs in <30s total, this is negligible but not zero.

2. **Dual execution paths.** The direct `run_pipeline()` function and the LangGraph `build_pipeline()` entrypoint create two ways to run the same logic. The direct path is the primary runtime; LangGraph is the extension point. This creates a maintenance surface.

3. **LangGraph version coupling.** The `langgraph>=0.2.0` pin means breaking changes in LangGraph's API could require pipeline rewrites. Mitigated by the direct execution path as fallback.

4. **Debugging LangGraph internals.** When the graph runtime misbehaves (e.g., state not flowing between nodes), debugging requires understanding LangGraph's internal state management, which is less transparent than a plain function call.

### Mitigations

- **Dual paths:** The direct `run_pipeline()` is the production runtime. LangGraph is the extension surface. Tests exercise both paths.
- **Version pin:** `langgraph>=0.2.0` in `pyproject.toml` with `uv.lock` for reproducibility.
- **State typing:** All 18 fields in `PipelineState` are typed with `NotRequired` for optional phases. Mypy catches missing fields at compile time.

## Implementation Notes

- `graph/state.py` defines `PipelineState(TypedDict, total=False)` with typed fields
- `graph/pipeline.py` implements both `run_pipeline()` (direct) and `build_pipeline()` (LangGraph)
- Search tiers run via `asyncio.gather()` inside `search_all` node — parallel within the node, sequential between nodes
- COLD/SKIP leads archive to JSONL via `archive_batch()` — never stored in ChromaDB
- Human approval gate at `await_human_send` sets `awaiting_approval=True` and halts the graph
